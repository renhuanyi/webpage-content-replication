# 统一验收规则

## 静态验收

验收器必须使用封存的 `capture-manifest` 作为独立基线，再与当前原始合并结果和正式输出逐层对照。不能写死某一页的标题、图片或 block 数，也不能只从当前 `page-data.json` 推导期望值后让它自证。至少输出：

- item 总数、ID 范围、缺口、重复项和归一化后的真冲突；
- 根 block 类型与最终输出类型对照；
- 标题、表格、网格、图片和未渲染 item 数量；
- 正文首尾、结构损失和媒体省略清单；
- 图片引用次数、唯一 URL、本地成功数、内嵌数、真实类型和可解码结果；
- HTML 中的远程媒体属性、远程渲染依赖、联网代码、未处理媒体入口；
- Markdown/HTML 文件大小与 SHA-256；
- manifest 与 `page-data.json` 的字节数、SHA-256、根块边界、递归数量和结构统计对照；
- manifest 与 `resource-index` 的字节数、SHA-256 和唯一资源数量对照；
- 敏感字段分类结果和正式输出中的敏感值泄漏检查。

## 浏览器验收

内容复刻和双交付至少验证：

- HTML 能直接通过 `file://` 打开；
- 首段、末段和关键章节存在；
- 图片按期望数量加载且有有效尺寸；
- 页面窄屏时图片、表格和网格不溢出；
- 无网络时页面仍能显示正文和图片；
- 已实现的目录、折叠、图片预览、搜索等交互分别可用。

视觉归档至少验证截图尺寸、序列重叠、末尾证据和清单一致性。

## 失败语言

- “文件已生成”只能表示文件存在。
- “资源包已下载”不能表示正文资源闭包完成。
- “ZIP 校验通过”只能表示压缩包可解压。
- 有缺口、真冲突、关键资源失败、结构未渲染或只能通过临时服务器打开时，写“未完成/待确认”，并列出具体项目。

新增或修改采集、构建或验收流程后，必须在临时副本运行负向测试：缺根块、缺本地资源、原始数据哈希变化、未知 block、未分类敏感字段和 reference 失联都应命中具体检查名。

## 最终回执

回执按所选模式写明：

1. 模式名称；
2. 正式交付文件的逐项可点击路径；
3. 验收结果和关键数量；
4. 结构、媒体、浏览器或权限边界；
5. ZIP（如有）仅作为附加封装。
