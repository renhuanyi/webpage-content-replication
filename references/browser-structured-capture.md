# 浏览器结构化采集

适用于 `content-replica`，也适用于 `dual-delivery` 的内容层。当用户已在授权的浏览器页面中打开目标内容，且页面运行环境已经加载出稳定的目标文档对象时，优先考虑此路径。它是可选的内容采集方法，不是所有网站的强制要求，也不取代视觉截图。

## 1. 适用条件

开始前确认：

- 目标页面、标题、来源 URL 和当前登录状态明确；
- 用户已有的登录态可以直接使用，不绕过登录；
- 页面已经加载出可定位的目标文档对象；
- 能区分目标文档对象和应用的其他状态；
- 任务允许保存页面正文和实际媒体引用。

如果无法确认目标对象边界，回退到稳定 DOM、可见文本、虚拟滚动窗口或截图流程，不导出整个应用状态。

## 2. 授权与敏感数据边界

只提取完成复刻所需的目标文档对象。禁止读取、打印或保存：

- Cookie；
- localStorage 或 sessionStorage 的全量内容；
- 请求头、密码、授权令牌、刷新令牌和秘密值；
- 与目标文档无关的用户资料、权限状态或应用缓存。

页面内部出现的 token 类字段默认按敏感字段处理。只有在明确证明它是内容资源标识、且确实参与目标资源获取时，才能记录字段类别和数量；不要把字段值写入日志、manifest、Markdown 或 HTML。未参与渲染或下载的字段应在持久化前剔除。

## 3. 采集顺序

```text
确认页面和授权范围
→ 定位目标文档对象
→ 提取最小结构化对象
→ 扫描并裁剪敏感字段
→ 在构建前封存 capture-manifest
→ 从合并正文的实际引用建立资源闭包
→ 生成 Markdown/HTML
→ 静态验收
→ file:// 和真实浏览器验收
```

原始结构化数据应作为不可变证据保存。manifest 一旦存在，默认拒绝覆盖；重新采集应建立新的证据目录或版本化快照。

## 4. capture-manifest 最低内容

manifest 至少记录：

- `schemaVersion`、`manifestKind`、封存时间；
- 来源 URL、页面标题、文档 ID；
- 原始结构化数据路径、字节数和 SHA-256；
- 根 block 数量、首尾索引、首尾稳定 ID；
- 递归 block 数量、根 block 类型统计、标题/表格/网格/图片数量；
- 资源索引路径、字节数、SHA-256 和唯一资源数量；
- 敏感字段扫描结果，但不记录敏感值；
- 是否为采集现场清单，还是对历史归档的补录。

历史补录必须明确标记为 `retrospective-baseline`，不得声称具备采集现场的独立性。

## 5. 资源和输出

图片、视频、附件和其他媒体必须先确定保留策略。图片资源闭包从合并后的正文实际检查 `src`、`data-src`、`poster`、`srcset`、`source`、CSS 背景图和 iframe 等入口；页面资源清单只能辅助，不能替代实际引用检查。

构建器必须保留未知 block 的诊断信息。未知 block、关键媒体失败或 manifest 哈希不一致时，阻断“内容复刻完成”的判断。

## 6. 非自证验收

验收必须至少包含两条独立对照链：

```text
capture-manifest → page-data → Markdown/HTML
capture-manifest → resource-index → 本地资源文件
```

不能只从当前 `page-data.json` 动态计算期望值，再用同一个文件证明自己正确。验证器不能写死某一页的标题、图片数或 block 数；页面专属数量只能存在于该页的封存 manifest 中。

## 7. 负向测试

新增或改动采集、构建或验收流程后，用临时副本验证至少这些错误能被捕获：

- 删除一个输出根 block；
- 删除一个被正文引用的本地资源；
- 改写原始数据导致 SHA-256 不一致；
- 注入未知 block 类型；
- 注入未分类的授权或会话字段；
- 移除本 reference 在 `SKILL.md` 中的路由链接。

负向测试必须命中具体检查名，不能只检查退出码。

## 8. 与截图流程的关系

结构化采集证明内容、顺序、嵌套关系和资源闭包；截图证明原页面的视觉状态、视口覆盖、折叠状态和末尾证据。用户要求视觉归档或双交付时，仍按 `visual-archive` 规则保存截图。结构化采集不可单独宣称像素级视觉复刻完成。
