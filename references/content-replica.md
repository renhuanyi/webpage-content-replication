# 内容复刻模式

适用于 `content-replica`，以及 `dual-delivery` 的正式内容层。

## 目标

必须同时交付两份独立、可定位的正式文件：

- `*.md`：完整可读的网页或文档正文，图片能在目标 Markdown 阅读环境中显示；
- `*.html`：可直接通过 `file://` 打开，正文和图片无需网络即可显示。

最终回复必须分别给出这两个文件的可点击路径，并附验收记录。不能只提供 ZIP、目录或资源包。

## 内容采集与合并

- 当授权的浏览器页面已经加载稳定的目标文档对象时，优先考虑 `browser-structured-capture`；它是内容层的可选优先路径，不取代视觉截图。
- 结构化原始数据在生成前必须有 `capture-manifest`；历史补录必须标记为 `retrospective-baseline`，不能伪称为采集现场清单。
- 结构化采集只保存目标文档对象，不保存 Cookie、localStorage/sessionStorage、请求头、密码、授权令牌或秘密值。详情见 [browser-structured-capture.md](browser-structured-capture.md)。
- 优先使用页面稳定 ID；没有稳定 ID 时，组合使用 DOM 路径、正文哈希、顺序锚点和窗口重叠，并在验收中标记置信度。
- 虚拟滚动窗口按稳定 ID 合并。比较重复项前归一化空白、动态 fragment 和临时框架属性；正文、根 block 类型或有效资源引用不同就阻断生成。
- 标题识别只能检查 item 根 block 类型，不能在整段 HTML 中搜索标题类名。表格、网格和卡片内部可以嵌套标题。
- 生成前后对照根 block 类型、标题、表格或网格、图片和未渲染 item 数量；数量必须从当前页面动态推导。
- 内容覆盖不能只用“生成文件包含采集文件”证明，还要有页面末尾证据、稳定 ID/顺序证据或截图/DOM 交叉证据。

## Markdown 保真

- 普通段落、标题、列表和引用保持阅读顺序与语义关系。
- 简单矩形表格转标准 Markdown 表格；复杂表格或网格优先在 Markdown 中嵌入 HTML。
- 只有用户明确接受降级时才把复杂结构线性化；线性化必须在验收中写明“结构未保留”。
- 文字完整不等于版式完整，不能把线性化结果称为结构完全复刻。
- 图片默认内嵌为自包含数据；若文件体积或目标阅读器不支持数据 URI，改用相对资源目录前必须在交付说明中明确。

## 离线 HTML

- 所有渲染所需图片、CSS、脚本和字体策略必须自包含或使用明确的相对本地路径。
- 不得依赖远程媒体、自动联网代码或外部 CSS/脚本才能显示正文。
- 正文中的外部超链接可以保留为点击后访问的内容，但不能把它们当作离线渲染依赖。
- 目录、折叠、图片预览、搜索等属于可选交互；实现了才验收，未实现不判为失败。
- 音视频、附件和特殊媒体必须在任务开始确定“内嵌、保留本地文件、提示省略或判未完成”的策略；不能无提示丢弃正文或图片。

## 内容模式完成条件

只有以下项目全部成立才能写“内容复刻完成”：

1. Markdown 和 HTML 两份正式文件分别存在且可定位；
2. 正文顺序、首尾和关键结构通过静态检查；
3. 正文实际引用的图片资源全部闭包，图片真实可解码；
4. HTML 通过 `file://` 直接打开并在无网络时显示；
5. 静态检查没有未渲染 item、关键媒体失败或未记录的远程依赖；
6. 最终回复分别提供 Markdown、HTML 和验收记录链接。
